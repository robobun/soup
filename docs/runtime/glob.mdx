## Quickstart

**Scan a directory for files matching `*.ts`**:

```ts
import { Glob } from "bun";

const glob = new Glob("**/*.ts");

// Scans the current working directory and each of its sub-directories recursively
for await (const file of glob.scan(".")) {
  console.log(file); // => "index.ts"
}
```

**Match a string against a glob pattern**:

```ts
import { Glob } from "bun";

const glob = new Glob("*.ts");

glob.match("index.ts"); // => true
glob.match("index.js"); // => false
```

To match many paths against one pattern, create the `Glob` once and reuse it. With any pattern, the time `match()` takes grows linearly with the length of the path.

The `Glob` class implements the following interface:

```ts
class Glob {
  constructor(pattern: string | string[]);

  scan(root: string | ScanOptions): AsyncIterable<string>;
  scanSync(root: string | ScanOptions): Iterable<string>;

  match(path: string): boolean;
}

interface ScanOptions {
  /**
   * The root directory to start matching from. Defaults to `process.cwd()`
   */
  cwd?: string;

  /**
   * Allow patterns to match entries that begin with a period (`.`).
   *
   * @default false
   */
  dot?: boolean;

  /**
   * Return the absolute path for entries.
   *
   * @default false
   */
  absolute?: boolean;

  /**
   * Indicates whether to traverse descendants of symbolic link directories.
   *
   * @default false
   */
  followSymlinks?: boolean;

  /**
   * Throw an error when symbolic link is broken
   *
   * @default false
   */
  throwErrorOnBrokenSymlink?: boolean;

  /**
   * Return only files.
   *
   * @default true
   */
  onlyFiles?: boolean;

  /**
   * Glob patterns for paths to leave out. A directory that matches is not entered.
   *
   * @default []
   */
  ignore?: string | string[];
}
```

## Several patterns

Pass an array to match any of several patterns with one `Glob`:

```ts
import { Glob } from "bun";

const glob = new Glob(["**/*.ts", "**/*.tsx", "package.json"]);

glob.match("src/index.ts"); // => true
glob.match("package.json"); // => true
glob.match("README.md"); // => false

for await (const file of glob.scan(".")) {
  console.log(file); // every .ts and .tsx file, and package.json
}
```

`match()` returns `true` for a path that one of the patterns matches. A scan returns what the scan of each pattern returns. It returns every path once, also when several patterns match it, and in no specified order. It takes the same options as the scan of one pattern.

An entry that starts with `!` excludes what it matches:

```ts
import { Glob } from "bun";

const glob = new Glob(["**/*.ts", "!**/node_modules/**", "!**/*.test.ts"]);

glob.match("src/index.ts"); // => true
glob.match("src/index.test.ts"); // => false
glob.match("node_modules/zod/index.ts"); // => false

await Array.fromAsync(glob.scan(".")); // no test file, and nothing under node_modules
```

Such an entry is the [`ignore` option](#ignoring-paths) written in the list:

- It applies to all the other entries, wherever it is in the array.
- A scan does not enter a directory that it matches, and `match()` returns `false` for every path below that directory.
- A scan matches it against the same path as an `ignore` pattern: the normalized path relative to `cwd`, or the full path if the entry that found the path is absolute.
- An odd number of `!` in front of an entry excludes. An even number does not. `!(` starts an extended glob pattern and does not count, and `\!` matches a literal `!`.
- An array without an entry that says what to match matches nothing, and a scan of it reads nothing. This is different from the `glob` option of `Bun.Archive`, where such a list includes everything else.

This is different from a single pattern that starts with `!`, which negates the pattern:

```ts
new Glob("!*.ts").match("index.js"); // => true: the pattern does not match
new Glob(["!*.ts"]).match("index.js"); // => false: nothing says what to match
```

A `./` in front of an entry makes no difference. `new Glob(["./src/*.ts", "src/*.ts"])` returns `src/index.ts` once, and `!./src/**` excludes what `!src/**` excludes. `match()` of an array ignores a `./` in front of the path too. Only the `./` in front counts for nothing: `src/./*.ts` returns `src/./index.ts`. A `../` or an absolute path stays in the paths that a scan returns: `["src/*.ts", "../lib/*.ts"]` returns `src/index.ts` and `../lib/index.ts`.

Write the entries with `/` on every platform. A `\` escapes the character after it.

Keep these limits in mind:

- A scan walks the patterns of an array one after the other, on one thread. Directories that several patterns reach are read once for each of them. When the patterns are in different directories and you scan asynchronously, a `Glob` for each pattern and `Promise.all` can be faster.
- If one pattern cannot start, the scan throws. An example is an absolute pattern in a directory that does not exist.
- A `{a,b}` or `@(a|b)` group that contains a `/` matches with `match()`, but a scan finds nothing for it. This is the same for a single pattern. Write such a group as separate entries: `["src/*.ts", "package.json"]` instead of `"{src/*.ts,package.json}"`. In an entry that starts with `!`, such a group works. There is one exception: for a `/` at the end of an alternative, as in `!{dist/,build/}`, a scan skips the directories, and `match()` still returns `true` for what is below them.
- `match()` does not know whether a path is a directory. `new Glob(["**", "!build/"]).match("build")` returns `true`, and a scan with `onlyFiles: false` does not return `build`.
- `match()` asks every `!` entry about all the directories above a path. A scan does not ask about the directories that an absolute pattern names before its first wildcard, or about a `..` at the start of a pattern. With `["/app/node_modules/zod/*.js", "!**/node_modules"]` a scan returns the files of `zod`, and `match()` returns `false` for them.

Bun reads the array when it creates the `Glob`. Changing the array later does not change the `Glob`.

## Ignoring paths

Pass `ignore` to leave paths out of the scan. It takes one glob pattern or an array of them, with the same syntax as the main pattern:

```ts
import { Glob } from "bun";

const glob = new Glob("**/*.ts");

for await (const file of glob.scan({
  ignore: ["**/node_modules/**", "dist/**", "**/*.test.ts"],
})) {
  console.log(file); // never a test file, and nothing under node_modules or dist
}
```

Bun matches a pattern against the normalized path relative to `cwd`, with `absolute` and without it. So `dist/**` only covers the `dist` directory at the root of the scan and `**/dist/**` covers every `dist` directory. If the scanned pattern is absolute, Bun matches against the full path.

A scan does not enter a directory that a pattern matches. `dist/**` and `dist/` match the directory `dist` too. `"**/node_modules/**"` therefore skips each `node_modules` tree instead of walking it and filtering its files afterwards, which is the part that makes a scan of a project directory slow. A pattern that ends with `/*`, such as `dist/*`, leaves out what is in `dist` and keeps `dist` itself.

A `./` in front of the scanned pattern or of an ignore pattern makes no difference. `new Glob("./**/*.ts")` returns `./src/index.ts`, and both `ignore: ["src/**"]` and `ignore: ["./src/**"]` leave it out.

## Supported Glob Patterns

Bun supports the following glob patterns:

### `?` - Match any single character

```ts
const glob = new Glob("???.ts");
glob.match("foo.ts"); // => true
glob.match("foobar.ts"); // => false
```

### `*` - Matches zero or more characters, except for path separators (`/` or `\`)

```ts
const glob = new Glob("*.ts");
glob.match("index.ts"); // => true
glob.match("src/index.ts"); // => false
```

### `**` - Match any number of characters including `/`

```ts
const glob = new Glob("**/*.ts");
glob.match("index.ts"); // => true
glob.match("src/index.ts"); // => true
glob.match("src/index.js"); // => false
```

### `[ab]` - Matches one of the characters contained in the brackets, as well as character ranges

```ts
const glob = new Glob("ba[rz].ts");
glob.match("bar.ts"); // => true
glob.match("baz.ts"); // => true
glob.match("bat.ts"); // => false
```

You can use character ranges (for example `[0-9]`, `[a-z]`). The negation operators `^` or `!` match anything _except_ the characters in the brackets (for example `[^ab]`, `[!a-z]`).

```ts
const glob = new Glob("ba[a-z][0-9][^4-9].ts");
glob.match("bar01.ts"); // => true
glob.match("baz83.ts"); // => true
glob.match("bat22.ts"); // => true
glob.match("bat24.ts"); // => false
glob.match("ba0a8.ts"); // => false
```

### `{a,b,c}` - Match any of the given patterns

```ts
const glob = new Glob("{a,b,c}.ts");
glob.match("a.ts"); // => true
glob.match("b.ts"); // => true
glob.match("c.ts"); // => true
glob.match("d.ts"); // => false
```

You can nest these patterns to any depth, and they can contain any of the other wildcards.

### `{1..3}` - Match a range of numbers or letters

```ts
const glob = new Glob("v{1..3}.ts");
glob.match("v1.ts"); // => true
glob.match("v3.ts"); // => true
glob.match("v4.ts"); // => false
```

| Pattern     | Matches                             |
| ----------- | ----------------------------------- |
| `{1..3}`    | `1`, `2`, `3`                       |
| `{01..10}`  | `01`, `02`, ..., `10` (zero-padded) |
| `{1..9..2}` | `1`, `3`, `5`, `7`, `9` (step of 2) |
| `{a..e}`    | `a`, `b`, `c`, `d`, `e`             |

### `@(a|b)` - Extended glob patterns

A `?`, `*`, `+`, `@` or `!` directly before a parenthesized list of patterns says how many of them to match.

| Pattern   | Matches                                        |
| --------- | ---------------------------------------------- |
| `?(a\|b)` | zero or one of the patterns                    |
| `*(a\|b)` | zero or more of the patterns                   |
| `+(a\|b)` | one or more of the patterns                    |
| `@(a\|b)` | exactly one of the patterns                    |
| `!(a\|b)` | anything in a path segment except the patterns |

```ts
const glob = new Glob("!(*.test).ts");
glob.match("index.ts"); // => true
glob.match("index.test.ts"); // => false
```

Parentheses without one of these prefixes are literal, so `app/(marketing)/**` matches the directory `app/(marketing)`.

### `!` - Negates the result at the start of a pattern

```ts
const glob = new Glob("!index.ts");
glob.match("index.ts"); // => false
glob.match("foo.ts"); // => true
```

In an [array of patterns](#several-patterns), an entry that starts with `!` does not negate. It leaves out what it matches.

### `\` - Escapes any of the special characters above

```ts
const glob = new Glob("\\!index.ts");
glob.match("!index.ts"); // => true
glob.match("index.ts"); // => false
```

## Node.js `fs.glob()` compatibility

Bun also implements Node.js's `fs.glob()` functions:

```ts
import { glob, globSync, promises } from "node:fs";

// Array of patterns
const files = await Array.fromAsync(promises.glob(["**/*.ts", "**/*.js"]));

// Exclude patterns
const filtered = await Array.fromAsync(
  promises.glob("**/*", {
    exclude: ["node_modules/**", "**/*.test.*"],
  }),
);
```

All three functions (`fs.glob()`, `fs.globSync()`, `fs.promises.glob()`) support:

- Array of patterns as the first argument
- `exclude` option to filter results
