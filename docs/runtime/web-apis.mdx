Some Web APIs, like the [DOM API](https://developer.mozilla.org/en-US/docs/Web/API/HTML_DOM_API#html_dom_api_interfaces) and [History API](https://developer.mozilla.org/en-US/docs/Web/API/History_API), aren't relevant in a server-first runtime like Bun. Many others are broadly useful outside the browser; when possible, Bun implements these Web-standard APIs instead of introducing new ones.

Bun partially or completely supports the following Web APIs.

## Web Storage

`sessionStorage` is a [`Storage`](https://developer.mozilla.org/en-US/docs/Web/API/Storage) that lives as long as the process. Every `Worker` has its own.

```ts
sessionStorage.setItem("theme", "dark");
sessionStorage.theme; // "dark"
sessionStorage.length; // 1
```

`localStorage` is kept in a file, and is a global only when `--localstorage-file` says which file. Without the flag `localStorage` is not defined.

```ts counter.ts
const runs = Number(localStorage.getItem("runs") ?? 0) + 1;
localStorage.setItem("runs", String(runs));
console.log(`run ${runs}`);
```

```sh
$ bun --localstorage-file=./local-storage.db counter.ts
run 1
$ bun --localstorage-file=./local-storage.db counter.ts
run 2
```

- The file is an SQLite database in the format that Node.js uses for its `--localstorage-file`, so the two runtimes can share one. It is created the first time `localStorage` is used. A relative path is resolved against the directory that the process started in.
- Several processes, and the `Worker`s of a process, can have the same file open. Each of them sees what the others write. The flag is for the whole process: a `Worker` cannot be given another file.
- `--localstorage-file=:memory:` is a `localStorage` that is not written anywhere, which is what a test run usually wants: `bun test --localstorage-file=:memory:`.
- A storage holds up to 10 MB of keys and values, counted as two bytes per UTF-16 code unit. A write that would go past that throws a `DOMException` named `QuotaExceededError`.
- Neither belongs to a request or a user. Everything that runs on a thread has the same `sessionStorage`, and everything that opens the file has the same `localStorage`, so a server should not put the data of one request or one user into them. With `:memory:` every `Worker` has a `localStorage` of its own.
