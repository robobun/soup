---
title: Archive
description: Create and extract tar and zip archives with Bun's fast native implementation
---

`Bun.Archive` is Bun's native API for tar and zip archives. It creates archives from in-memory data, extracts archives to disk, and reads archive contents without extraction.

## Quickstart

**Create an archive from files:**

```ts
const archive = new Bun.Archive({
  "hello.txt": "Hello, World!",
  "data.json": JSON.stringify({ foo: "bar" }),
  "nested/file.txt": "Nested content",
});

// Write to disk
await Bun.write("bundle.tar", archive);
```

**Extract an archive:**

```ts
const tarball = await Bun.file("package.tar.gz").bytes();
const archive = new Bun.Archive(tarball);
const entryCount = await archive.extract("./output");
console.log(`Extracted ${entryCount} entries`);
```

**Read archive contents without extracting:**

```ts
const tarball = await Bun.file("package.tar.gz").bytes();
const archive = new Bun.Archive(tarball);
const files = await archive.files();

for (const [path, file] of files) {
  console.log(`${path}: ${await file.text()}`);
}
```

## Creating Archives

Use `new Bun.Archive()` to create an archive from an object where keys are file paths and values are file contents. By default, the archive is a tar and it is not compressed. Pass `{ format: "zip" }` for a [zip archive](#zip-archives):

```ts
// Creates an uncompressed tar archive (default)
const archive = new Bun.Archive({
  "README.md": "# My Project",
  "src/index.ts": "console.log('Hello');",
  "package.json": JSON.stringify({ name: "my-project" }),
});
```

File contents can be:

- **Strings** - Text content
- **Blobs** - Binary data
- **ArrayBufferViews** (such as `Uint8Array`) - Raw bytes
- **ArrayBuffers** - Raw binary data

```ts
const data = "binary data";
const arrayBuffer = new ArrayBuffer(8);

const archive = new Bun.Archive({
  "text.txt": "Plain text",
  "blob.bin": new Blob([data]),
  "bytes.bin": new Uint8Array([1, 2, 3, 4]),
  "buffer.bin": arrayBuffer,
});
```

### Writing Archives to Disk

Use `Bun.write()` to write an archive to disk:

```ts
// Write uncompressed tar (default)
const archive = new Bun.Archive({
  "file1.txt": "content1",
  "file2.txt": "content2",
});
await Bun.write("output.tar", archive);

// Write gzipped tar
const compressed = new Bun.Archive({ "src/index.ts": "console.log('Hello');" }, { compress: "gzip" });
await Bun.write("output.tar.gz", compressed);

// Write a zip
const zip = new Bun.Archive({ "src/index.ts": "console.log('Hello');" }, { format: "zip" });
await Bun.write("output.zip", zip);
```

`Bun.write()`, `Bun.file().write()` and a write to S3 put the same bytes at the destination that `archive.bytes()` returns. The format and the compression are the ones of the archive, whatever the destination is called.

### Getting Archive Bytes

Get the archive data as bytes or a Blob:

```ts
const archive = new Bun.Archive({ "hello.txt": "Hello, World!" });

// As Uint8Array
const bytes = await archive.bytes();

// As Blob
const blob = await archive.blob();

// With gzip compression (set at construction)
const gzipped = new Bun.Archive({ "hello.txt": "Hello, World!" }, { compress: "gzip" });
const gzippedBytes = await gzipped.bytes();
const gzippedBlob = await gzipped.blob();
```

## Extracting Archives

### From Existing Archive Data

Create an archive from existing tar, tar.gz or zip data:

```ts
// From a file
const tarball = await Bun.file("package.tar.gz").bytes();
const archiveFromFile = new Bun.Archive(tarball);
```

```ts
// From a fetch response
const response = await fetch("https://example.com/archive.tar.gz");
const archiveFromFetch = new Bun.Archive(await response.blob());
```

```ts
// A zip
const zip = new Bun.Archive(await Bun.file("package.zip").bytes(), { format: "zip" });
```

`format` says what the data is, and Bun reads it as that and as nothing else. Without `format`, Bun reads the data as a tar or a gzipped tar, and as a zip if it is not a tar. See [the format of existing data](#the-format-of-existing-data).

### Extracting to Disk

Use `.extract()` to write all files to a directory:

```ts
const tarball = await Bun.file("package.tar.gz").bytes();
const archive = new Bun.Archive(tarball);
const count = await archive.extract("./extracted");
console.log(`Extracted ${count} entries`);
```

`extract()` creates the target directory if it doesn't exist and overwrites existing files. The returned count includes files, directories, and symlinks (on POSIX systems).

**Note**: On Windows, Bun always skips symbolic links during extraction, regardless of privilege level. On Linux and macOS, Bun extracts symlinks normally.

**Security note**: Bun.Archive validates paths during extraction. It rejects absolute paths (POSIX `/`, Windows drive letters like `C:\` or `C:/`, and UNC paths like `\\server\share`) and unsafe symlink targets. It normalizes away path traversal components (`..`) to prevent directory escape attacks: `dir/sub/../file` becomes `dir/file`.

On Linux and macOS, `extract()` also stays inside the target directory when that directory already contains symlinks, including symlinks from an archive you extracted there earlier:

- Bun does not write through a symlink that leads out of the target directory, or through one with an absolute target. When a file entry needs such a symlink, `extract()` rejects, or skips the entry if you pass a glob. The `code` of the error is `"EXDEV"`, and its `path` is where Bun would have written the entry, relative to the target directory. Extraction stops at that entry, and what Bun has already written stays. A symlink that Bun cannot resolve at all, such as a loop, is a `ReadError` without a `code`. `extract()` skips a directory entry that needs one.
- Bun follows a relative symlink that stays inside the target directory.
- Bun creates a symlink entry only in a directory that it reaches without following a symlink, and skips the entry otherwise.

On Windows, `extract()` does not check the junctions and symlinks that already exist in the target directory.

On Linux 5.6 or later, Bun resolves these paths with the `openat2` system call, and resolves them itself where a seccomp policy answers `openat2` with `ENOSYS` or `EPERM`. If your seccomp policy kills the process instead, set `BUN_FEATURE_FLAG_DISABLE_RESOLVE_BENEATH=1` so that Bun never makes the call.

### Filtering Extracted Files

Use glob patterns to extract only specific files. Bun matches patterns against archive entry paths normalized to use forward slashes (`/`). Positive patterns specify what to include, and negative patterns (prefixed with `!`) specify what to exclude. When you pass only negative patterns, Bun includes all entries that don't match them:

```ts
const tarball = await Bun.file("package.tar.gz").bytes();
const archive = new Bun.Archive(tarball);

// Extract only TypeScript files
const tsCount = await archive.extract("./extracted", { glob: "**/*.ts" });

// Extract files from multiple directories
const multiCount = await archive.extract("./extracted", {
  glob: ["src/**", "lib/**"],
});
```

When mixing positive and negative patterns, entries must match at least one positive pattern and no negative pattern:

```ts
// Extract everything except node_modules
const distCount = await archive.extract("./extracted", {
  glob: ["**", "!node_modules/**"],
});

// Extract source files but exclude tests
const srcCount = await archive.extract("./extracted", {
  glob: ["src/**", "!**/*.test.ts", "!**/__tests__/**"],
});
```

## Reading Archive Contents

### Get All Files

Use `.files()` to get archive contents as a `Map` of `File` objects without extracting to disk. Unlike `extract()`, which processes all entry types, `files()` returns only regular files (no directories):

```ts
const tarball = await Bun.file("package.tar.gz").bytes();
const archive = new Bun.Archive(tarball);
const files = await archive.files();

for (const [path, file] of files) {
  console.log(`${path}: ${file.size} bytes`);
  console.log(await file.text());
}
```

Each `File` object includes:

- `name` - The file path within the archive (always uses forward slashes `/` as separators)
- `size` - File size in bytes
- `lastModified` - Modification timestamp
- Standard `Blob` methods such as `text()`, `arrayBuffer()`, and `stream()`

**Note**: `files()` loads file contents into memory. For large archives, use `extract()` to write directly to disk instead.

The holes of a sparse file take no space in the archive, and `files()` reads them as zeros. `files()` rejects once the holes it has read from one archive add up to more than 1,024 times the size of the archive as it was given, so the compressed size of a `.tar.gz`. It always reads up to 64 MiB of holes and never more than 1 GiB. `extract()` has no such limit, because it leaves holes unallocated on disk.

### Error Handling

Archive operations can fail due to corrupted data, I/O errors, or invalid paths. Use try/catch to handle these cases:

```ts
try {
  const tarball = await Bun.file("package.tar.gz").bytes();
  const archive = new Bun.Archive(tarball);
  const count = await archive.extract("./output");
  console.log(`Extracted ${count} entries`);
} catch (e: unknown) {
  if (e instanceof Error) {
    const error = e as Error & { code?: string };
    if (error.code === "EACCES") {
      console.error("Permission denied");
    } else if (error.code === "ENOSPC") {
      console.error("Disk full");
    } else {
      console.error("Archive error:", error.message);
    }
  } else {
    console.error("Archive error:", String(e));
  }
}
```

Common error scenarios:

- **Corrupted/truncated archives** - `new Bun.Archive()` loads the archive data; Bun may defer errors until read/extract operations
- **Permission denied** - `extract()` throws if the target directory is not writable
- **Disk full** - `extract()` throws if there's insufficient space
- **Invalid paths** - Operations throw for malformed file paths

For additional security with untrusted archives, you can enumerate and validate paths before extraction:

```ts
const archive = new Bun.Archive(untrustedData);
const files = await archive.files();

// Optional: Custom validation for additional checks
for (const [path] of files) {
  // Example: Reject hidden files
  if (path.startsWith(".") || path.includes("/.")) {
    throw new Error(`Hidden file rejected: ${path}`);
  }
  // Example: Whitelist specific directories
  if (!path.startsWith("src/") && !path.startsWith("lib/")) {
    throw new Error(`Unexpected path: ${path}`);
  }
}

// Extract to a controlled destination
await archive.extract("./safe-output");
```

When called with a glob pattern, `files()` returns an empty `Map` if no files match:

```ts
const matches = await archive.files("*.nonexistent");
if (matches.size === 0) {
  console.log("No matching files found");
}
```

### Filtering with Glob Patterns

Pass a glob pattern to filter which files are returned:

```ts
// Get only TypeScript files
const tsFiles = await archive.files("**/*.ts");

// Get files in src directory
const srcFiles = await archive.files("src/*");

// Get all JSON files (recursive)
const jsonFiles = await archive.files("**/*.json");

// Get multiple file types with array of patterns
const codeFiles = await archive.files(["**/*.ts", "**/*.js"]);
```

Supported glob patterns (subset of [Bun.Glob](/runtime/glob) syntax):

- `*` - Match any characters except `/`
- `**` - Match any characters including `/`
- `?` - Match single character
- `[abc]` - Match character set
- `{a,b}` - Match alternatives
- `!pattern` - Exclude files matching pattern (negation). When you pass only negative patterns, Bun includes all files not matching them.

See [Bun.Glob](/runtime/glob) for the full glob syntax including escaping and advanced patterns.

## Compression

Bun.Archive creates uncompressed tar archives by default. Use `{ compress: "gzip" }` to enable gzip compression:

```ts
// Default: uncompressed tar
const archive = new Bun.Archive({ "hello.txt": "Hello, World!" });

// Reading: automatically detects gzip
const gzippedTarball = await Bun.file("archive.tar.gz").bytes();
const readArchive = new Bun.Archive(gzippedTarball);

// Enable gzip compression
const compressed = new Bun.Archive({ "hello.txt": "Hello, World!" }, { compress: "gzip" });

// Gzip with custom level (1-12)
const maxCompression = new Bun.Archive({ "hello.txt": "Hello, World!" }, { compress: "gzip", level: 12 });
```

The `options` argument accepts:

- No options or `undefined` - Uncompressed tar (default)
- `{ compress: "gzip" }` - Enable gzip compression at level 6
- `{ compress: "gzip", level: number }` - Gzip with custom level 1-12 (1 = fastest, 12 = smallest)
- `{ format: "zip" }` - A zip archive with each file deflated at level 6
- `{ format: "zip", level: number }` - A zip archive with each file deflated at level 1-12
- `{ format: "zip", compress: "store" }` - A zip archive with its files as they are

A tar archive takes `"gzip"`. A zip archive that is created from an object takes `"deflate"` or `"store"`. Every other combination throws a `TypeError`, and so does `level` together with `"store"`.

Existing archive data that is gzip already stays as it is with `{ compress: "gzip" }`. Bun does not compress it a second time. Existing data that is a zip takes no `compress` at all.

## Zip archives

`Bun.Archive` creates a zip archive from an object when you pass `{ format: "zip" }`, and reads one with the same methods as a tar archive:

```ts
// Create
const archive = new Bun.Archive(
  {
    "README.md": "# My Project",
    "src/index.ts": "console.log('Hello');",
    "empty-directory/": "",
  },
  { format: "zip" },
);
await Bun.write("project.zip", archive);

// Read
const zip = new Bun.Archive(await Bun.file("project.zip").bytes(), { format: "zip" });
const files = await zip.files();
await zip.extract("./project");
```

### The format of existing data

With existing data, `format` is your word for what the data is. `{ format: "zip" }` reads it as a zip and `{ format: "tar" }` as a tar or a gzipped tar. Data that is not what you said is an error when it is read.

Without `format`, Bun guesses. It reads the data as a tar, and as a zip only if the data is not a tar. The guess can be wrong: one file can be a valid tar and a valid zip at the same time, with other files in each, and `unzip`, Python, Go and Node.js read the zip in such a file. Pass `format` for data that you did not make yourself.

Bun never takes the format from a file name, and an `Archive` keeps the format that it has.

### Creating

- Each file is compressed with DEFLATE by itself, and a file that does not get smaller is stored as it is. `{ compress: "store" }` stores every file.
- Bun compresses on a thread pool when the archive is written or its bytes are read, not in the constructor.
- A value is a string, a `Blob`, a `TypedArray` or an `ArrayBuffer`. Every other value throws a `TypeError`, where a tar archive stores `String(value)`. A `Bun.file()` or an S3 file throws too: pass `await file.bytes()`.
- A key that ends in `/` with an empty value is a directory. With any other value it throws a `TypeError`.
- The entries come from an object. A `Map` throws a `TypeError`: pass `Object.fromEntries(map)`.
- A name is recorded in UTF-8. On Windows, a `\` in a key becomes `/`, which is what a zip has between the parts of a path on every system.
- Every entry gets the time of the constructor call and mode `0644` (`0755` for a directory). The time is recorded twice: in UTC, and as local time in the MS-DOS fields, where programs that do not know the UTC field look.
- Bun writes the ZIP64 records only when an archive needs them: for 65,535 entries or more, and for sizes and offsets of 4 GiB or more.

To make a zip of a tar, read the files of the tar and create a new archive from them:

```ts
const tar = new Bun.Archive(await Bun.file("project.tar.gz").bytes(), { format: "tar" });
const zip = new Bun.Archive(Object.fromEntries(await tar.files()), { format: "zip" });
await Bun.write("project.zip", zip);
```

`files()` returns regular files only. The new archive has no directory entries and no symlinks, and its files have mode `0644` and the time of the conversion.

### Reading

`files()`, `extract()` and their glob filters work on a zip as they do on a tar, and `files()` returns regular files only. `extract()` follows the same rules for paths and symlinks as for a tar.

What an entry is:

- The name is the Info-ZIP Unicode Path field if the entry has one for its name. Such a field that is not UTF-8 is an error. Without the field, the name is UTF-8 if the entry says so or if its bytes are valid UTF-8, and code page 437 otherwise.
- In a name from MS-DOS (the FAT host) that has no `/`, a `\` is a `/`. `unzip` has the same rule.
- A name that ends in `/` is a directory. A symlink is an entry from Unix with the mode of a symlink. Every other entry is a regular file, whatever its mode says.
- The permissions are the ones of the Unix mode. An entry without permissions, as in every archive that was not made on Unix, is `0644`, and a directory `0755`.
- The modification time is the UTC time of the "extended timestamp" field. An entry without that field has only its MS-DOS date and time, and Bun reads them as local time.
- A symlink target is read when the symlink is made, and a target of more than 4,096 bytes is an error then. `files()` and a glob that leaves the symlink out do not read it.

What Bun checks:

- Bun reads the central directory at the end of the archive and takes every fact about an entry from it. It accepts data in front of the archive, such as the program of a self-extracting archive, and an archive comment.
- The local header of each entry has to agree with the central directory about the name, the compression method and the encryption flags. The CRC-32 and the sizes have to agree too. If the entry has a data descriptor, the local header can have zeros for them. Bun does not read the data descriptor, and it does not look at bytes that no entry of the directory covers.
- Bun rejects an archive in which two entries share bytes. A zip bomb is made that way: one compressed file with thousands of entries that point at it. Without shared bytes, an archive unpacks to no more than DEFLATE can make of it, about 1,032 times its size.
- Bun checks each file against the size and the CRC-32 that the archive records. `files()` and `extract()` reject at the first file that differs. What `extract()` has already written stays.
- An archive without ZIP64 records counts its entries in 16 bits. Bun reads an archive with more entries whose count wrapped around.
- The ZIP64 end record is the one that the locator names, and it has to end where the locator starts. If there is data in front of the archive, it is the record directly in front of the locator. Bun rejects an archive where the locator names a record somewhere else, because other programs do not agree on which record counts.

Not supported: encrypted entries, compression methods other than "stored" and DEFLATE, and archives that span several disks. An entry that is encrypted or uses another method is an error when Bun reads its contents, so a glob that leaves it out still extracts the rest.

## Examples

### Bundle Project Files

```ts
import { Glob } from "bun";

// Collect source files
const files: Record<string, string> = {};
const glob = new Glob("src/**/*.ts");

for await (const path of glob.scan(".")) {
  // Normalize path separators to forward slashes for cross-platform compatibility
  const archivePath = path.replaceAll("\\", "/");
  files[archivePath] = await Bun.file(path).text();
}

// Add package.json
files["package.json"] = await Bun.file("package.json").text();

// Create compressed archive and write to disk
const archive = new Bun.Archive(files, { compress: "gzip" });
await Bun.write("bundle.tar.gz", archive);
```

### Extract and Process npm Package

```ts
const response = await fetch("https://registry.npmjs.org/lodash/-/lodash-4.17.21.tgz");
const archive = new Bun.Archive(await response.blob());

// Get package.json
const files = await archive.files("package/package.json");
const packageJson = files.get("package/package.json");

if (packageJson) {
  const pkg = JSON.parse(await packageJson.text());
  console.log(`Package: ${pkg.name}@${pkg.version}`);
}
```

### Create Archive from Directory

```ts
import { readdir } from "node:fs/promises";
import { join } from "node:path";

async function archiveDirectory(dir: string, compress = false): Promise<Bun.Archive> {
  const files: Record<string, Blob> = {};

  async function walk(currentDir: string, prefix: string = "") {
    const entries = await readdir(currentDir, { withFileTypes: true });

    for (const entry of entries) {
      const fullPath = join(currentDir, entry.name);
      const archivePath = prefix ? `${prefix}/${entry.name}` : entry.name;

      if (entry.isDirectory()) {
        await walk(fullPath, archivePath);
      } else {
        files[archivePath] = Bun.file(fullPath);
      }
    }
  }

  await walk(dir);
  return new Bun.Archive(files, compress ? { compress: "gzip" } : undefined);
}

const archive = await archiveDirectory("./my-project", true);
await Bun.write("my-project.tar.gz", archive);
```

## Reference

> **Note**: The following type signatures are simplified. See [`packages/bun-types/bun.d.ts`](https://github.com/oven-sh/bun/blob/main/packages/bun-types/bun.d.ts) for the full type definitions.

```ts
type ArchiveInput =
  Record<string, string | Blob | Bun.ArrayBufferView | ArrayBufferLike> | Blob | Bun.ArrayBufferView | ArrayBufferLike;

type ArchiveOptions = {
  /** With an object: what to create (default "tar"). With existing data: what the data is (default: a guess). */
  format?: "tar" | "zip";
  /** "gzip" for tar (default: none). "deflate" (default) or "store" for a zip that is created from an object. */
  compress?: "gzip" | "deflate" | "store";
  /** Compression level 1-12 (default 6). */
  level?: number;
};

interface ArchiveExtractOptions {
  /** Glob pattern(s) to filter extraction. Supports negative patterns with "!" prefix. */
  glob?: string | readonly string[];
}

class Archive {
  /**
   * Create an Archive from input data
   * @param data - Files to archive (as object) or existing archive data (as bytes/blob)
   * @param options - Format and compression options. An uncompressed tar by default.
   *                  Pass { compress: "gzip" } to enable compression, or { format: "zip" } for a zip.
   */
  constructor(data: ArchiveInput, options?: ArchiveOptions);

  /**
   * Create an archive and write it to a file
   */
  static write(path: string, data: ArchiveInput | Archive, options?: ArchiveOptions): Promise<void>;

  /**
   * Extract archive to a directory
   * @returns Number of entries extracted (files, directories, and symlinks)
   */
  extract(path: string, options?: ArchiveExtractOptions): Promise<number>;

  /**
   * Get archive as a Blob (uses the format and compression settings from the constructor)
   */
  blob(): Promise<Blob>;

  /**
   * Get archive as a Uint8Array (uses the format and compression settings from the constructor)
   */
  bytes(): Promise<Uint8Array<ArrayBuffer>>;

  /**
   * Get archive contents as File objects (regular files only, no directories)
   */
  files(glob?: string | readonly string[]): Promise<Map<string, File>>;
}
```
