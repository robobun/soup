Bun upgrades itself with the built-in `bun upgrade` command.

```bash terminal icon="terminal"
bun upgrade
```

`bun upgrade` downloads and installs the latest stable version of Bun, replacing the currently installed version. If you're on a canary build, `bun upgrade` installs the latest canary build instead.

<Note>To see the current version of Bun, run `bun --version`.</Note>

---

## Verify the upgrade

After upgrading, verify the new version:

```bash terminal icon="terminal"
bun --version
# Output: 1.x.y

# See the exact commit of the Bun binary
bun --revision
# Output: 1.x.y+abc123def
```

---

## Upgrade to canary builds

Canary builds are published automatically from the `main` branch once a commit's CI tests pass. They're useful for trying new features or verifying bug fixes before a release.

```bash terminal icon="terminal"
bun upgrade --canary
```

<Warning>Canary builds are not recommended for production use. They may contain bugs or breaking changes.</Warning>

---

## Switch back to stable

If you're on a canary build and want to return to the latest stable release:

```bash terminal icon="terminal"
bun upgrade --stable
```

---

## Install a specific version

To install a specific version of Bun, newer or older than the current one, pass the version to `bun upgrade`:

```bash terminal icon="terminal"
bun upgrade 1.3.3
```

`v1.3.3`, `bun-v1.3.3` and `--version 1.3.3` name the same release. `bun upgrade` checks the download against the SHA-256 that GitHub lists for the release, runs the new binary to check its version, and then replaces the current binary. Releases up to v1.2.15 were published without a SHA-256: they are installed without that check, with a warning.

<Warning>
  An older release does not have the security fixes of the releases after it. Read the [security
  advisories](https://github.com/oven-sh/bun/security/advisories) before you stay on one.
</Warning>

<Note>
  A release that is older than this feature does not take a version. The install script below installs any version,
  whatever release is installed, so use it to go back. An older release may also not read a lockfile or a cache that a
  newer release wrote.
</Note>

To run another version once, without replacing the installed one, use `bunx bun@1.3.3`.

The install script also takes a version tag:

<Tabs>
  <Tab title="macOS & Linux">
    ```bash terminal icon="terminal"
    curl -fsSL https://bun.sh/install | bash -s "bun-v1.3.3"
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell PowerShell icon="windows"
    iex "& {$(irm https://bun.sh/install.ps1)} -Version 1.3.3"
    ```
  </Tab>
</Tabs>

## Package manager users

If you installed Bun with a package manager, upgrade with that package manager instead of `bun upgrade` to avoid conflicts.

<Tip>
**Homebrew users** <br />
Use `brew upgrade bun` instead.

**Scoop users** <br />
Use `scoop update bun` instead.

</Tip>
