Configure `bun test` with `bunfig.toml` and command-line options.

## Configuration File

To configure `bun test` in `bunfig.toml`, add a `[test]` section:

```toml title="bunfig.toml" icon="settings"
[test]
# Options go here
```

## Test Discovery

### root

The `root` option sets the directory Bun scans for tests, instead of the project root.

```toml title="bunfig.toml" icon="settings"
[test]
root = "src"  # Only scan for tests in the src directory
```

#### Examples

```toml title="bunfig.toml" icon="settings"
[test]
# Only run tests in the src directory
root = "src"

# Run tests in a specific test directory
root = "tests"

# Run tests in multiple specific directories (not currently supported - use patterns instead)
# root = ["src", "lib"]  # This syntax is not supported
```

### testMatch

`testMatch` sets which files `bun test` runs as tests, using glob patterns. The patterns replace the default names, so a project can name its tests `*.unit.ts`, or keep them in a `tests/` directory without a suffix.

```toml title="bunfig.toml" icon="settings"
[test]
# Single pattern
testMatch = "tests/**"

# Multiple patterns
testMatch = ["**/*.unit.ts", "**/*.int.ts"]
```

This is equivalent to using `--test-match` on the command line:

```bash terminal icon="terminal"
bun test --test-match '**/*.unit.ts' --test-match '**/*.int.ts'
```

Patterns use the same syntax as [`Bun.Glob`](/runtime/glob). Bun matches them against the path of a file relative to the project root, which is the directory you run `bun test` in. `tests/**` is the `tests` directory of the project, and `**/tests/**` is one at any depth. A `./` at the start of a pattern is dropped.

To keep the default names next to your own, add them as a pattern:

```toml title="bunfig.toml" icon="settings"
[test]
testMatch = ["**/*{.,_}{test,spec}.{js,jsx,ts,tsx,mjs,cjs,mts,cts}", "**/*.unit.ts"]
```

#### Negated patterns

A pattern that starts with `!` takes files away. As in Jest, Bun asks the patterns in order and the last one that has a say decides. A pattern has a say on the paths it matches, and a negated pattern on the paths it rejects:

```toml title="bunfig.toml" icon="settings"
[test]
testMatch = [
  "tests/**",             # every file under tests/
  "!tests/helpers/**",    # but nothing under tests/helpers/
  "tests/helpers/e2e.ts"  # except this file
]
```

A list of only negated patterns takes files away from the default names: `testMatch = ["!e2e/**"]` runs the `*.test.*` and `*.spec.*` files that are not under `e2e/`.

#### What else decides

`testMatch` changes which names are tests, and nothing else about discovery:

- A test file still needs an extension that Bun loads as JavaScript or TypeScript, so `tests/**` doesn't run `tests/data.json` or a snapshot. To run files with another extension, map it in [`[loader]`](/runtime/bunfig#loader).
- Bun doesn't scan `node_modules` or directories whose name starts with a period.
- [`pathIgnorePatterns`](#path-ignore-patterns) excludes files that `testMatch` names.
- Filters narrow the list further. `bun test cart` runs the files that `testMatch` names and that have `cart` in their path.
- A file path on the command line, such as `bun test ./scratch.ts`, runs whether or not a pattern matches it.

<Note>Command-line `--test-match` flags replace the `bunfig.toml` value for the run. Bun does not merge the two.</Note>

With `testMatch` set, [`coverageSkipTestFiles`](#skip-test-files-from-coverage) leaves out the files that the patterns name instead of the files with a default test name. A run with `--test-match` leaves out both: the files that the flag names and the files that `testMatch` in `bunfig.toml` names, or without one the default names. The tests you didn't ask for this time don't turn up as uncovered source.

#### Lists from Jest and Vitest

The `testMatch` of a Jest config and the `include` of a Vitest config work as they are written:

```toml title="bunfig.toml" icon="settings"
[test]
# Jest's default
testMatch = ["**/__tests__/**/*.[jt]s?(x)", "**/?(*.)+(spec|test).[jt]s?(x)"]

# Vitest's default
testMatch = ["**/*.{test,spec}.?(c|m)[jt]s?(x)"]
```

Bun reads two things the way Jest does, because Jest lists rely on them:

- A group with alternatives needs no prefix: `**/*.(spec|test).ts` is `**/*.@(spec|test).ts`. Parentheses without a `|` are text, as in `Bun.Glob`, so `app/(marketing)/**` is a directory.
- `<rootDir>/` at the start of a pattern is the directory in [`root`](#root), or the project root without one.

Three things differ from Jest:

- Patterns are relative to the project root. Jest matches absolute paths, so a pattern that starts with an absolute path finds nothing here.
- `**.test.ts` only matches files in the project root. Write `**/*.test.ts`.
- Square brackets are a character class. For a directory such as `[id]`, write `\\[id\\]` in `bunfig.toml`.

`testRegex` has no equivalent.

#### Other file types

To run files that aren't JavaScript as tests, pair `testMatch` with a [plugin](/runtime/plugins) that turns them into test code. This runs every `.feature` file:

```toml title="bunfig.toml" icon="settings"
[test]
testMatch = ["features/**/*.feature"]
preload = ["./feature-plugin.ts"]

[loader]
".feature" = "ts"
```

```ts title="feature-plugin.ts" icon="/icons/typescript.svg"
import { plugin } from "bun";

plugin({
  name: "feature",
  setup(build) {
    build.onLoad({ filter: /\.feature$/ }, async args => {
      const source = await Bun.file(args.path).text();
      return { contents: toTests(source), loader: "ts" }; // your code that writes test() calls
    });
  },
});
```

### Preload Scripts

The `preload` option loads scripts before the tests run:

```toml title="bunfig.toml" icon="settings"
[test]
preload = ["./test-setup.ts", "./global-mocks.ts"]
```

This is equivalent to using `--preload` on the command line:

```bash terminal icon="terminal"
bun test --preload ./test-setup.ts --preload ./global-mocks.ts
```

#### Common Preload Use Cases

```ts title="test-setup.ts" icon="/icons/typescript.svg"
// Global test setup
import { beforeAll, afterAll } from "bun:test";

beforeAll(() => {
  // Set up test database
  setupTestDatabase();
});

afterAll(() => {
  // Clean up
  cleanupTestDatabase();
});
```

```ts title="global-mocks.ts" icon="/icons/typescript.svg"
// Global mocks
import { mock } from "bun:test";

// Mock environment variables
process.env.NODE_ENV = "test";
process.env.API_URL = "http://localhost:3001";

// Mock external dependencies
mock.module("./external-api", () => ({
  fetchData: mock(() => Promise.resolve({ data: "test" })),
}));
```

### Environment

`environment` sets the DOM that test files run with. It can be `"happy-dom"`, `"jsdom"`, or `"node"` for no DOM (the default). The package has to be installed in your project. See [DOM testing](/test/dom#test-environments).

```toml title="bunfig.toml" icon="settings"
[test]
environment = "happy-dom"
```

The `--environment` flag does the same thing and overrides `bunfig.toml`:

```bash terminal icon="terminal"
bun test --environment=happy-dom
```

A `// @vitest-environment <name>` comment in a test file overrides both. So does a `/** @jest-environment <name> */` comment at the very top of the file.

### Globals

By default, `test`, `expect` and the other globals come from `"bun:test"`. A file that imports anything from `"vitest"` gets them from `"vitest"` instead. If that file is a test file or a preload script, so do the modules it loads.

Set `globals = "vitest"` to get them from `"vitest"` in every file, like `globals: true` in a Vitest project. See [what differs](/test/writing-tests#importing-from-vitest).

```toml title="bunfig.toml" icon="settings"
[test]
globals = "vitest" # default "bun"
```

The `--globals` flag overrides `bunfig.toml`. Write it with `=`, as in `--globals=vitest`.

- With `globals = "vitest"`, the names are also properties of `globalThis`, as in Vitest. Some packages look for `globalThis.afterEach` there.
- Imports from `"bun:test"` and `"@jest/globals"` keep those modules' behavior.
- `true` and `false`, the values Vitest takes, are accepted and change nothing. So is `--globals` without a value.
- If a preload script sets one of these globals itself (`globalThis.expect = chai.expect`), files that import from `"bun:test"`, `"@jest/globals"` or `"vitest"` keep the preload's value.
- As in Vitest, the `"vitest"` globals don't include `jest`, `xit`, `xtest` or `xdescribe`.
- Vitest also defines `assert` and `chai` as globals. Bun doesn't, so import `assert` from `"vitest"`.
- For their types, see [`bun-types/vitest-globals`](/test/writing-tests#types).
- A module keeps the globals it was first loaded with. With `--isolate`, it keeps them until the next file. So a library loaded by a preload script sees `jest`, unless that script imports from `"vitest"` or `globals = "vitest"` is set.

Libraries such as `@testing-library/dom` look for a global `jest` and use it to advance fake timers while they wait. Without one, they leave the clock alone. To make them advance it, use `vi.useFakeTimers({ shouldAdvanceTime: true })` or set `globalThis.jest = { advanceTimersByTime: ms => vi.advanceTimersByTime(ms) }`.

### React Compiler

`bun test` can compile your components and hooks with Bun's built-in [React Compiler](https://react.dev/learn/react-compiler), so that your tests run what your build ships. The compiled code imports `react/compiler-runtime`, which React 19 has. This option is experimental.

```toml title="bunfig.toml" icon="settings"
[test]
reactCompiler = true # default false
```

Bun compiles every JavaScript and TypeScript file except test files, preload scripts and `node_modules`. It leaves alone a file or a function that has the `"use no memo"` directive, and a function that breaks the [Rules of React](https://react.dev/reference/rules).

To compile part of a project, list folders or glob patterns. They are relative to the directory you run `bun test` in.

```toml title="bunfig.toml" icon="settings"
[test]
reactCompiler = ["src", "packages/ui"]
```

Use a table to leave out some of what's in them:

```toml title="bunfig.toml" icon="settings"
[test.reactCompiler]
include = ["src", "packages/ui"]
exclude = ["**/*.stories.*", "**/__mocks__/**"]
```

- A folder includes everything inside it. `"."` is the directory you run `bun test` in, and `"../../packages/ui"` is a folder outside of it.
- A glob pattern is matched against the file's path relative to that directory. `**` also matches `..`, so `**/*.stories.*` applies to the folders outside of it too.
- A workspace package that is linked into `node_modules` is compiled. List it by its real path, like `"../../packages/ui"`.

The `--react-compiler` flag turns the compiler on for one run. It compiles what `bunfig.toml` includes, or every file if `bunfig.toml` doesn't say.

- What `importOriginal()` and `vi.importActual()` load is compiled like any other import of that file.
- A module that isn't a file, like a `data:` URL, isn't compiled.
- To check that a function was compiled, look for its cache in the source: `/\$\d*\[\d+\]/.test(String(Component))`.

### Path Ignore Patterns

`pathIgnorePatterns` excludes files and directories from test discovery entirely, using glob patterns. Unlike `coveragePathIgnorePatterns`, which only affects coverage reports, `pathIgnorePatterns` prevents Bun from discovering matching paths and running them as tests.

Use it when your project contains submodules, vendored code, or other directories with `*.test.ts` files that you don't want `bun test` to pick up.

```toml title="bunfig.toml" icon="settings"
[test]
# Single pattern
pathIgnorePatterns = "vendor/**"

# Multiple patterns
pathIgnorePatterns = [
  "vendor/**",
  "submodules/**",
  "fixtures/**"
]
```

This is equivalent to using `--path-ignore-patterns` on the command line:

```bash terminal icon="terminal"
bun test --path-ignore-patterns 'vendor/**' --path-ignore-patterns 'fixtures/**'
```

Bun prunes directories matching a pattern during scanning and never traverses their contents, so ignoring a large directory tree is cheap.

#### Common Use Cases

```toml title="bunfig.toml" icon="settings"
[test]
pathIgnorePatterns = [
  # Git submodules with their own test suites
  "submodules/**",

  # Vendored dependencies
  "vendor/**",
  "third-party/**",

  # Test fixtures that look like tests but aren't
  "fixtures/**",
  "**/test-data/**",

  # Integration / E2E tests you want to run separately
  "**/integration/**",
  "e2e/**"
]
```

<Note>
  Command-line `--path-ignore-patterns` flags override the `bunfig.toml` value entirely. Bun does not merge the two.
</Note>

## Reporters

### JUnit Reporter

Configure the JUnit reporter output file path directly in the config file:

```toml title="bunfig.toml" icon="settings"
[test.reporter]
junit = "path/to/junit.xml"  # Output path for JUnit XML report
```

This complements the `--reporter=junit` and `--reporter-outfile` CLI flags:

```bash terminal icon="terminal"
# Equivalent command line usage
bun test --reporter=junit --reporter-outfile=./junit.xml
```

### JSON Reporter

The JSON reporter writes the results in Jest's `--json` format. Configure its output file path the same way:

```toml title="bunfig.toml" icon="settings"
[test.reporter]
json = "path/to/results.json"  # Output path for the JSON report
```

```bash terminal icon="terminal"
# Equivalent command line usage
bun test --reporter=json --reporter-outfile=./results.json
```

#### Multiple Reporters

You can use multiple reporters simultaneously:

```bash terminal icon="terminal"
# CLI approach
bun test --reporter=junit --reporter-outfile=./junit.xml

# Config file approach
```

```toml title="bunfig.toml" icon="settings"
[test.reporter]
junit = "./reports/junit.xml"

[test]
# Also enable coverage reporting
coverage = true
coverageReporter = ["text", "lcov"]
```

## Memory Usage

### smol Mode

Enable the `--smol` memory-saving mode specifically for the test runner:

```toml title="bunfig.toml" icon="settings"
[test]
smol = true  # Reduce memory usage during test runs
```

This is equivalent to using the `--smol` flag on the command line:

```bash terminal icon="terminal"
bun test --smol
```

The `smol` mode reduces memory usage by:

- Using less memory for the JavaScript heap
- Being more aggressive about garbage collection
- Reducing buffer sizes where possible

Use it in memory-constrained environments, such as CI runners, or for large test suites.

## Test execution

### concurrentTestGlob

Run test files matching a glob pattern with concurrent test execution enabled.

```toml title="bunfig.toml" icon="settings"
[test]
concurrentTestGlob = "**/concurrent-*.test.ts"  # Run files matching this pattern concurrently
```

Test files matching the pattern behave as if you passed the `--concurrent` flag: every test in those files runs concurrently. Use this to migrate a test suite to concurrent execution gradually, or to run one kind of test (say, integration tests) concurrently while the rest stay sequential.

The `--concurrent` CLI flag overrides this setting, forcing all tests to run concurrently regardless of the glob pattern.

#### randomize

Run tests in random order to identify tests with hidden dependencies:

```toml title="bunfig.toml" icon="settings"
[test]
randomize = true
```

#### seed

Specify a seed for reproducible random test order. Requires `randomize = true`:

```toml title="bunfig.toml" icon="settings"
[test]
randomize = true
seed = 2444615283
```

#### retry

Default retry count for all tests. Bun retries a failed test up to this many times. Per-test `{ retry: N }` overrides this value. Default `0` (no retries).

```toml title="bunfig.toml" icon="settings"
[test]
retry = 3
```

The `--retry` CLI flag overrides this setting.

#### rerunEach

Re-run each test file multiple times to identify flaky tests:

```toml title="bunfig.toml" icon="settings"
[test]
rerunEach = 3
```

#### clearMocks, mockReset, restoreMocks, unstubEnvs, unstubGlobals

Clean up the previous test's mocks and stubs. The cleanup runs before each test and each retry, ahead of the `beforeEach` hooks. The option names and the order they run in are the same as Vitest's:

```toml title="bunfig.toml" icon="settings"
[test]
restoreMocks = true   # mock.restore() / vi.restoreAllMocks()
mockReset = true      # vi.resetAllMocks()
clearMocks = true     # mock.clearAllMocks()
unstubEnvs = true     # vi.unstubAllEnvs()
unstubGlobals = true  # vi.unstubAllGlobals()
```

They're all off by default, except that `clearMocks` is on for tests that use `test` from `"vitest"`, like in Vitest 5. Set `clearMocks = false` to turn that off. `vi.setConfig({ clearMocks: true })` changes an option for the rest of the test file.

## Coverage Options

### Basic Coverage Settings

```toml title="bunfig.toml" icon="settings"
[test]
# Enable coverage by default
coverage = true

# Set coverage reporter
coverageReporter = ["text", "lcov"]

# Set coverage output directory
coverageDir = "./coverage"
```

### Skip Test Files from Coverage

Exclude files matching test patterns (for example `*.test.ts`) from the coverage report:

```toml title="bunfig.toml" icon="settings"
[test]
coverageSkipTestFiles = true  # Exclude test files from coverage reports
```

### Coverage Thresholds

Specify the coverage threshold as a single number or as an object with per-metric thresholds:

```toml title="bunfig.toml" icon="settings"
[test]
# Simple threshold - applies to lines and functions
coverageThreshold = 0.8

# Detailed thresholds
coverageThreshold = { lines = 0.9, functions = 0.8 }
```

Setting a threshold makes `bun test` exit with code 1 when coverage is enabled and any file's line or function coverage is below it. Bun accepts the `statements` key but does not currently enforce it. The check applies with any coverage reporter.

#### Threshold Examples

```toml title="bunfig.toml" icon="settings"
[test]
# Require 90% coverage across the board
coverageThreshold = 0.9

# Different requirements for different metrics
coverageThreshold = {
  lines = 0.85,      # 85% line coverage
  functions = 0.90   # 90% function coverage
}
```

### Files to Cover

Name the files the coverage report is about with glob patterns. The report then has every file the list names, including the ones that no test loaded, and no other file:

```toml title="bunfig.toml" icon="settings"
[test]
# Single pattern
collectCoverageFrom = "src/**"

# Multiple patterns, asked in order. A pattern that starts with "!" takes files out.
collectCoverageFrom = ["src/**", "!src/generated/**"]
```

```bash terminal icon="terminal"
# Replaces the list in bunfig.toml
bun test --coverage --collect-coverage-from 'src/**'
```

A file that nothing loaded has no line and no function covered and counts towards `coverageThreshold`. See [Choosing the files to cover](/test/code-coverage#choosing-the-files-to-cover).

### Coverage Path Ignore Patterns

Exclude specific files or file patterns from coverage reports using glob patterns:

```toml title="bunfig.toml" icon="settings"
[test]
# Single pattern
coveragePathIgnorePatterns = "**/*.spec.ts"

# Multiple patterns
coveragePathIgnorePatterns = [
  "**/*.spec.ts",
  "**/*.test.ts",
  "src/utils/**",
  "*.config.js",
  "generated/**",
  "vendor/**"
]
```

Bun excludes files matching any of these patterns from coverage calculation and reporting. See [Code coverage](/test/code-coverage).

To leave single lines, functions or a whole file out of the report from inside the source, use a comment such as `/* v8 ignore next */`. See [Ignoring code with comments](/test/code-coverage#ignoring-code-with-comments).

#### Common Ignore Patterns

```toml title="bunfig.toml" icon="settings"
[test]
coveragePathIgnorePatterns = [
  # Test files
  "**/*.test.ts",
  "**/*.spec.ts",
  "**/*.e2e.ts",

  # Configuration files
  "*.config.js",
  "*.config.ts",
  "webpack.config.*",
  "vite.config.*",

  # Build output
  "dist/**",
  "build/**",
  ".next/**",

  # Generated code
  "generated/**",
  "**/*.generated.ts",

  # Vendor/third-party
  "vendor/**",
  "third-party/**",

  # Utilities that don't need testing
  "src/utils/constants.ts",
  "src/types/**"
]
```

### Sourcemap Handling

Bun transpiles every file, so coverage results pass through sourcemaps before they're reported. `coverageIgnoreSourcemaps` opts out of this, but the results are confusing: during transpilation, Bun may move code around and rename variables. The option is mostly useful for debugging coverage issues.

```toml title="bunfig.toml" icon="settings"
[test]
coverageIgnoreSourcemaps = true  # Don't use sourcemaps for coverage analysis
```

<Warning>
  When using this option, you probably want to stick a `// @bun` comment at the top of the source file to opt out of the
  transpilation process.
</Warning>

## Install Settings Inheritance

`bun test` inherits network and installation configuration (such as `registry`, `cafile`, `prefer`, and `exact`) from the `[install]` section of `bunfig.toml`. This matters if your tests reach a private registry or trigger installs during the run.

```toml title="bunfig.toml" icon="settings"
[install]
# These settings are inherited by bun test
registry = "https://npm.company.com/"
exact = true
prefer = "offline"

[test]
# Test-specific configuration
coverage = true
```

## Environment Variables

Set environment variables for tests with `.env` files, which Bun loads from your project root automatically. For test-specific variables, create a `.env.test` file, which `bun test` loads automatically:

```ini title=".env.test" icon="settings"
NODE_ENV=test
DATABASE_URL=postgresql://localhost:5432/test_db
LOG_LEVEL=error
```

## Complete Configuration Example

An example showing the available test configuration options:

```toml title="bunfig.toml" icon="settings"
[install]
# Install settings inherited by tests
registry = "https://registry.npmjs.org/"
exact = true

[test]
# Test discovery
root = "src"
preload = ["./test-setup.ts", "./global-mocks.ts"]
testMatch = ["**/*.test.ts", "**/*.unit.ts"]
pathIgnorePatterns = ["vendor/**", "submodules/**"]

# Execution settings
smol = true

# Coverage configuration
coverage = true
coverageReporter = ["text", "lcov"]
coverageDir = "./coverage"
coverageThreshold = { lines = 0.85, functions = 0.90 }
coverageSkipTestFiles = true
collectCoverageFrom = ["src/**"]
coveragePathIgnorePatterns = [
  "**/*.spec.ts",
  "src/utils/**",
  "*.config.js",
  "generated/**"
]

# Advanced coverage settings
coverageIgnoreSourcemaps = false

# Reporter configuration
[test.reporter]
junit = "./reports/junit.xml"
```

## CLI Override Behavior

Command-line options always override configuration file settings:

```toml title="bunfig.toml" icon="settings"
[test]
coverage = false
```

```bash terminal icon="terminal"
# This CLI flag overrides the config file
bun test --coverage
# coverage will be enabled
```
